# Configuring a run

How to change what the chain does for one KHG or for all of them, check the change, and rerun what it affects. Works the same
in Docker (docs/22) and on a workstation (docs/19); only the place of your files differs.

## Where settings live

Four layers, each winning over the one before:

| Layer | File | Who writes it |
|---|---|---|
| 1. National template | `re-peat/pipeline.yaml` | the team (tracked) |
| 2. Your national choices | Docker: `REPEAT_DIR/config/settings.yaml`; workstation: `re-peat/pipeline.local.yaml` | you |
| 3. Facts of one KHG | `re-peat/sites/<folder>/khg.yaml` | generated by `init`; never edit it |
| 4. Exceptions for one KHG | Docker: `REPEAT_DIR/config/overrides/<code>.yaml`; tracked for the team: `re-peat/sites/<folder>/overrides.yaml` | you |

Layer 2 takes any key of `pipeline.yaml`; layer 4 takes the KHG's own data (`peat_depth`, `dems`, `canals`) and, under `steps:`,
any key of the step sections. Write only what you change, with a comment saying why and when.

## Every option, with examples

| File | What it holds |
|---|---|
| [config/settings.example.yaml](config/settings.example.yaml) | every national setting at today's value, commented out: copy the lines you need into layer 2 |
| [config/overrides.example.yaml](config/overrides.example.yaml) | every per-KHG setting, commented out: copy into layer 4 |
| [config/pump-settings.md](config/pump-settings.md) | every key of the pump's run config that `pump.set` takes (112 on 2026-11-11), with the model default, the proposed default, what the chain sets, and a note |
| [21-configuration.md](21-configuration.md) | the same settings as one table: English name, Indonesian label, unit, allowed values, meaning |

All four are generated from the code (`python tools/khg_pipeline.py config catalogue`), so they list exactly what the chain
accepts.

Common changes:

```yaml
# layer 2 (all KHG you run)
dems:
  default: [deltadtm]                 # DeltaDTM only; [lidar, deltadtm] is the national default
neraca:
  rain: imerg                         # chirps (default), imerg, terraclimate_pr
  et: [mod16]                         # wapor, mod16, mod16nrt, terraclimate_aet
pump:
  set:
    run.subkhg_selection.n: 8         # plan 8 sub-KHG (national choice: 5)
    optimise.n_blocks: 15             # choose 15 blocks (proposed default: 10)
```

```yaml
# layer 4, e.g. config/overrides/14.08.04.yaml
peat_depth:                           # your own peat-depth raster, in REPEAT_DIR/data/
  source: modelled raster
  path: ${REPEAT_DATA}/my_peat_depth_mandiangin.tif
  scale: 0.01                         # cm; 1 if the raster is in metres
dems:
  lidar: {skip: "not used in this comparison (2026-11-11)"}
steps:
  delineation: {min_area_km2: 10}
  pump:
    set: {interventions.held_target: 0.6, optimise.objective: screen_then_pde}
```

Your own LiDAR needs no setting: put the GeoTIFF in `data/lidar_own/` and the DEM step clips it (docs/22, section 4).

## Check before running

    config validate --khg <code>     # typos, wrong values, missing files, unknown pump keys; exits with an error on problems
    config show --khg <code>         # every setting the KHG's steps read, its value, and the file it comes from

(In Docker: `docker compose run --rm chain config validate --khg <code>`; on a workstation: `python tools/khg_pipeline.py ...`.)
`show` is the way to confirm your file is the one in effect.

## Rerun after a change

The chain skips a step whose output exists; it does not notice a changed setting. After a change, rerun from the first step it
affects, and everything after it:

    run --khg <code> --from <step>

| You changed | `--from` |
|---|---|
| DEMs (`dems`), your own LiDAR | `dem_inputs` |
| peat depth (`peat_depth`) | `local_inputs` |
| DEM correction (`dem_correction`) | `dem_correction` |
| delineation | `delineation` |
| rain, ET, periods (`neraca`) | `deficit` |
| prioritisation | `prioritisation` |
| pump settings (`pump`) | `pump` |

`plan --khg <code> --from <step>` lists what would run first. `--dem deltadtm` limits a rerun to one DEM.

## Comparing two configurations

A rerun replaces the KHG's results. To keep both, copy the KHG's work folder (`khg/<folder>`) before the rerun, or use a second
`REPEAT_DIR` for the other configuration. Named runs side by side are not built yet.
